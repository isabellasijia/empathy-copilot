# 共情双舱

面向美妆电商人工客服的服务记忆与风险协同系统。项目使用赛题官方 MOCK 数据，将聊天、订单和五类售后工单整理为可追溯的客服工作流。

## 已实现

- 官方 Excel 数据清洗、字段标准化和 SQLite 入库
- 聊天、订单、工单和承诺的统一会话视图
- Qwen 动态会话理解、建议回复和发送前质检，未配置时自动使用本地规则
- 消费者端与客服工作台双向消息同步，新消息入库不等待模型推理
- 消费者可拍照或上传 JPG、PNG、WebP，真实图片随聊天进入 Qwen 多模态分析
- 图片识别结果与订单、工单交叉核对，客服端仅展示可见事实、置信提示和人工复核建议
- 基于用户主动提供的信息生成轻量服务画像，不推断无关或敏感属性
- 消费者发送后后台预热 Qwen 分析，客服端先显示新消息，再动态更新情绪、意图和草稿
- Qwen 草稿在展示前通过确定性护栏，自动改写无依据承诺、错误实体和重复追问
- 色号、SKU 和不良反应的确定性风险检查
- 客服编辑后的独立发送前质检和高风险拦截
- 风险事件的证据回溯、负责人、截止时间和状态更新
- 小型可审核知识库和关键词检索
- 客服页精选 4 个典型案例，分别覆盖跨系统核对、图片凭证、不良反应安全回访和个性化建议
- 真实未读消息状态、AI 首接与显式/风险转人工
- 基于工单与履约证据的服务状态机，已完结业务直接完成，明确未解决则重新核对
- 最新轮次优先的层级意图候选，支持否定、转折、多意图歧义和超范围兜底
- 按意图、情绪、风险、回复安全与服务记忆分组的 15 项可复算评测
- 规则先行的按需 Agent 编排，复杂诉求才调用深度模型
- 订单、工单、服务记忆、图片核对、风险检查与知识检索 Skill
- BM25、本地 N-gram 向量、场景过滤与 RRF 融合的混排 RAG
- 客户—会话—订单—工单—SKU 的轻量服务关系图

## 启动

需要 Python 3.10 或更高版本。

在 macOS 上可以直接双击项目根目录中的 `双击启动.command`。它会在首次运行时自动创建环境、安装依赖，并打开客服工作台；终端窗口需保持打开。

也可以手动启动：

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env
```

在 `.env` 中填入新生成的 Key，不要把 Key 写入源码或提交到 Git。

```dotenv
DASHSCOPE_API_KEY=sk-your-new-key
DASHSCOPE_BASE_URL=https://ws-cbx8yygvhh809a77.cn-beijing.maas.aliyuncs.com/compatible-mode/v1
QWEN_TEXT_MODEL=qwen-turbo
QWEN_OMNI_MODEL=qwen3-omni-flash-2025-12-01
```

启动前后端：

```bash
chmod +x scripts/run_dev.sh scripts/test.sh
./scripts/run_dev.sh
```

打开 `http://127.0.0.1:4173/`。消费者 H5 位于 `http://127.0.0.1:4173/consumer?case=S00018`，效果评测台位于 `http://127.0.0.1:4173/evaluation`，API 文档位于 `http://127.0.0.1:4173/docs`。

双端演示时，先在消费者端发送一条消息，客服工作台会自动收到并刷新服务建议；客服端回复后，消费者端会自动显示新回复。

图片上传限制为 4 MB；浏览器会先将常见手机照片缩放到最长边 1600 像素。官方 MOCK 数据中的历史图片只有路径、没有原文件，因此仅对消费者端新上传的真实图片执行图像理解，不把缺失文件标记为已识别。

## 评测与成本

`GET /api/evaluation` 会重放 15 个固定场景，覆盖跨系统冲突、回复安全、情绪变化、解决确认、转人工，以及意图识别中的否定、转折、多意图歧义和超范围请求。这是可复算的核心回归集，不冒充大规模线上准确率。

成本优化包括：会话分析缓存、同会话并发请求合并、前端草稿去重、AI 首次回复快速通道，以及“首条问题 + 最近 12 条 + 结构化业务记忆”的上下文压缩策略。纯文本分析与回复使用低成本 `qwen-turbo`，只有真实图片进入 `qwen3-omni-flash`；服务启动后会在后台预热文本模型，歧义复核仅发送最新消息、上一条用户消息和候选意图，图片与文本任务并行执行。

调度层会先运行本地特征、业务查询和风险规则。高置信意图直接走本地快速通道；候选差值过小、超范围、风险或图片场景才调用深度理解模型。简单问候、感谢和确认不调用深度理解模型；图片理解只在存在真实图片时触发；长回复或涉及退款、补发、赔偿和医疗表述时才触发深度质检。客服页面不展示这些实现术语，独立效果评测台展示真实 Skill 路由、检索分数和模型成本。

意图识别的设计参考了 [JointBERT](https://arxiv.org/abs/1902.10909) 的意图与槽位联合理解思路、[CLINC150](https://arxiv.org/abs/1909.02027) 对超范围请求的评测方法，以及 [Rasa FallbackClassifier](https://rasa.com/docs/rasa/2.x/components/#fallbackclassifier) 的置信度和候选差值兜底机制。当前 Demo 用可解释的本地候选打分完成第一层路由，并让 Qwen 只复核歧义轮次；后续有标注数据时可直接替换为微调分类器，不改变上层工作流。

混排 RAG 使用审核知识作为高权威来源，同时收录 1 条 Open Beauty Facts 公开产品样例用于验证来源和许可证追溯。公开产品数据不能替代品牌官方配方、功效或安全结论。

未配置 Key 时项目仍可启动，页面会标记为「演示模式」并使用确定性规则。

## 安全边界

项目不自动发货、退款、修改工单或做医疗诊断。所有高风险动作由人工确认。官方数据中仅有图片路径，没有图片文件，因此当前版本不宣称已完成真实图像理解。
